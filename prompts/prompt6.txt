# Part 4 — Correct Ready Queue Behavior in Round-Robin

Some tests show incorrect process ordering (e.g., selecting P7 before P6).

This typically occurs when:

* a running process is requeued
* new arrivals occur during the same tick
* queue insertion order is incorrect

The correct Round-Robin rule is:

```
When a quantum expires and the process still has remaining burst:
    push it to the BACK of the ready queue
```

However:

```
New arrivals during the same tick
must be inserted BEFORE the requeued process.
```

Correct event order should be:

```
1) arrivals added to ready queue
2) if running process quantum expired -> requeue it
3) scheduler selects next process
```

This ordering ensures fairness and matches the reference solution.
