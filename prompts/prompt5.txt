# Engineer Prompt 5 — Redirect Output to `.out` File

The scheduler implementation is now nearly complete and working correctly.
The remaining task is to ensure the program **writes its output to the correct `.out` file instead of printing to the console**.

Do **not rewrite working scheduling logic**. This change should be **minimal and safe**.

---

# Part 1 — Create the Output File

After parsing the input file, determine the output filename using the existing helper:

```
output_filename(input)
```

Then create the output file using standard Rust file APIs.

Example design approach:

* Use `std::fs::File`
* Wrap it in `std::io::BufWriter` for efficient writing

Example structure:

```
let file = File::create(output_path)?;
let mut writer = BufWriter::new(file);
```

---

# Part 2 — Replace `println!` With File Writing

All scheduler output should be written to the `.out` file instead of the console.

Recommended approach:

Use:

```
writeln!(writer, "text here")?;
```

instead of:

```
println!("text here");
```

This allows writing formatted lines directly into the output file.

---

# Part 3 — Pass the Writer to Simulation Functions

The scheduler functions currently print events internally.

Update their signatures so they **receive a mutable writer reference**.

Example:

```
fn simulate_fcfs(config: &Config, writer: &mut impl Write) -> Vec<Process>
fn simulate_sjf(config: &Config, writer: &mut impl Write) -> Vec<Process>
fn simulate_rr(config: &Config, writer: &mut impl Write) -> Vec<Process>
```

Using `impl Write` keeps the functions flexible and idiomatic.

Inside those functions replace all printing with:

```
writeln!(writer, ...)
```

# Part 5 — Error Handling

Use proper error propagation where possible.

Examples:

```
use std::io::{Write, BufWriter};
```

Return errors if writing fails instead of silently ignoring them.

The simulator specification expects output in the `.out` file.

Therefore:

* **Do not print scheduling events to stdout**
* Only fatal errors may appear on stderr if necessary
