# Part 3 — Fix Preemptive SJF

The current SJF implementation has two issues.

### Issue 1 — Incorrect selection timing

Currently it checks the shortest job **every tick**.

Instead the correct logic is:

```
When:
  - a new process arrives
  - the current process finishes

Then:
  choose the process with the shortest remaining burst time
  among ALL ready processes INCLUDING the currently running one
```

This more accurately represents **Shortest Remaining Time First scheduling**.

You may still check every tick internally, but structure the logic so that **selection only happens when an event occurs**.

---

### Issue 2 — Duplicate "selected" printing

Currently the code sets:

```
running = None
```

before checking whether the same process continues running.

This causes the "selected" message to always print.

Fix this so that:

* If the **same process continues running**, do **not** print another "selected" message.
* Only print `"selected"` when the **running process actually changes**.
