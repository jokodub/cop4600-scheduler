# Part 1 — Fix Event Ordering (Root Cause)

Currently finish events are printed using `time + 1` at the **end of the loop**.

Because of this, a finish event may be printed **before arrival events that occur at the same tick**.

Example incorrect ordering:

```
Time 5 : P1 finished
Time 5 : P2 arrived
```

Correct ordering must always be:

```
Time 5 : P2 arrived
Time 5 : P1 finished
```

---

# Correct Event Order Per Tick

At the start of each tick, the scheduler must process events in this order:

```
1) Print new arrivals
2) Print finish events
3) Perform scheduling decisions
4) Execute the CPU for the tick
```

---

# Required Structural Change

Move the **finish detection logic** so it executes **immediately after arrival handling**.

Instead of printing the finish event when it occurs at the end of the previous tick, store that state and print it at the **beginning of the next loop iteration**.

This guarantees:

```
arrivals -> finishes -> scheduling
```

# Part 2 — Round-Robin Queue Ordering

Ensure the following ordering inside Round-Robin:

```
1) arrivals are added to ready queue
2) finished processes are handled
3) quantum expiration requeues the running process
4) scheduler selects next process
```

The key rule:

```
new arrivals must enter the queue before a preempted process is requeued
```

This fixes the observed cases where:

```
P7 is selected before P6
```

when P6 actually arrived earlier.
